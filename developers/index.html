Platform / API direction
ExpenseIntel should eventually travel wherever the decision happens.

One cost engine. Many surfaces.

The long-term platform is an address-and-operating-profile interface that other underwriting, brokerage, acquisition and portfolio systems can call. Today this page documents the internal beta architecture only; it is not a public API contract.

01 / Current internal services

The data spine already exists.

ExpenseIntel currently separates address resolution, energy evidence and hazard evidence into server-side services. That modularity is what makes a future external cost-passport API possible.

ServiceCurrent roleEvidenceExternal status
/api/addressResolve U.S. address, coordinates, geography and tractCensus geocoder / provider abstractionInternal beta
/api/energyState end-use price + building-use intensity layerU.S. EIA + CBECS/bridge benchmarksInternal beta
/api/riskTract hazard-loss contextFEMA National Risk IndexInternal beta
/api/marketRepresentative U.S. electricity market scanU.S. EIAInternal beta
NOT A PUBLIC CONTRACT: These endpoints have no authentication, quota, uptime guarantee or versioning promise for third-party use yet.
02 / Future Cost Passport API

The object other products should consume.

The external interface should eventually return a standardized Cost Passport rather than forcing partners to reconstruct ExpenseIntel's source logic themselves.

{
  "address": "verified property address",
  "operating_profile": { "use": "industrial", "sqft": 100000 },
  "annual_cost": { "estimate": 1180000, "range": [1070000, 1300000] },
  "forecast": { "year_1": 1220000, "year_3": 1310000 },
  "commitment_grade": "B+",
  "evidence_coverage": 78,
  "drivers": ["electricity", "property_tax", "insurance"],
  "sources": [{ "layer": "electricity", "type": "authoritative" }]
}
